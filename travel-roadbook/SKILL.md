# 旅行路书规划

把用户的出行想法变成**经过里程核实的行程**，并产出一个手机可打开的**路书网页链接**（高德地图一键打开 + 天气 + 逐日路书 + 门票花费 + 穿着建议 + 注意事项）。

## 工作流程

### 1. 问清需求（一次问完）

用 `interaction.ask` 一次性问齐：出发地/目的地与具体日期天数、出行方式（自驾/高铁飞机+租车/公共交通，自驾问车型、司机数、可接受的单日里程）、人数与构成（老人小孩、是否上高原）、目的偏好与明确不想去的地方、预算与住宿档次。清单与问法见 `references/roadbook-spec.md` 第一节。用户已上传行程表时先完整读表，不重复询问。

### 2. 核实与质疑（核心价值，不能省）

- 逐段用高德工具实测里程与时长，**不要信用户表格里的里程或直线距离**；实测低估是常态（曾发现用户表低估达 112%）。
- 按 `references/planning-rules.md` 逐条校验：单日驾驶时长、过夜中点、高原海拔阶梯、节假日放假与错峰、"不想去 X 地"是过境还是绕开（两条线里程都算给用户）、环线与游玩密度。
- 涉及法定节假日，用 general_search 核实当年放假安排（政府网为准）并算清年假天数。
- 发现不合理处：明确指出问题、给替代方案和里程对比，关键取舍（如绕路与否）让用户拍板后再定稿。

### 3. 采集信息

- 坐标、里程、天气、POI、行程地图：按 `references/amap-tools.md` 的顺序调用高德 MCP 工具（调用前若 schema 不在上下文，先 `tool_search` 取回）。
- 天气只有未来约 4 天预报：覆盖不到的日期按同期气候参考，并在页面注明查询日期。
- 景点/美食/门票：高德 POI 为主；门票价格、预约规则（尤其 5A/限流景区、区间车索道二次消费）用 general_search 核实，标注价格时效。
- 穿着建议：按沿途最低夜温和场景（高原/徒步/雨/日晒）给分层穿搭。

### 4. 生成高德行程地图

用 `maps_schema_personal_map`（orgName + lineList，节点含 name/lon/lat/poiId，按行程时间排序）拿到 `amapuri://` 链接。该链接只能写进路书网页按钮，不能直接交付（交付工具不接受非 http(s) 链接）。

### 5. 构建路书网页

- 复制 `assets/roadbook.sample.json` 为本次数据文件，按 `references/roadbook-spec.md` 的字段规范填写全部模块（天气、逐站路书、门票与花费、穿着建议、注意事项）。
- 运行 `python3 scripts/build_roadbook.py <data.json> <输出.html>` 生成自包含手机端页面。
- 用 html 技能 `scripts/shot.py` 自检（重点看移动端：consoleErrors、横向溢出、时间轴对齐）。

### 6. 发布与交付

- 按 `references/roadbook-spec.md` 第四节用 `lark-cli apps +deploy` 发布（首发记 app_id，迭代带 `--app-id`），轮询 release 到 finished，curl 验证 200。
- 用户需要扫码时用 `scripts/make_qr.py` 对发布后的 https 链接生成二维码（不要编码 amapuri）。
- 用 `present_files` 交付 https 链接（及二维码），最终回复 ≤300 字，说明模块与数据查询日期、提示远期天气/价格出发前再核实。

## 参考文件（按需读取）

- `references/roadbook-spec.md`：需求询问清单、路书 JSON 字段、内容口径、自检/发布/二维码/交付全流程。**每次产出必读。**
- `references/planning-rules.md`：行程合理性质疑规则（里程阈值、高原、节假日、绕路权衡、非自驾变体）。规划阶段必读。
- `references/amap-tools.md`：高德 MCP 工具参数、调用顺序、lineList 结构与实测坑。调用高德工具前必读。

## 资产与脚本

- `assets/roadbook.sample.json`：路书数据模板（含字段示例，直接复制改写）。
- `scripts/build_roadbook.py`：JSON → 自包含路书 HTML（已内置样式、复制链接按钮、天气网格、时间轴、门票表、穿着卡片）。
- `scripts/make_qr.py`：发布链接 → 二维码 PNG。
